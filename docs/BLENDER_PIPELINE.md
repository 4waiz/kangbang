# Blender asset pipeline

Every 3D model in KANG BANG is generated by Python that lives in this
repository. There is no binary source art, no downloaded asset, and nothing that
cannot be reproduced from a clean checkout.

```
assets/scripts/lib_kang.py       shared authoring library
assets/scripts/gen_weapons.py    10 weapons (FP + world) + first-person arms
assets/scripts/gen_characters.py 6 class bodies
assets/scripts/gen_props.py      32 props, pickups, objectives, deployables
        │
        │  tools/build-assets.mjs  (finds Blender, runs each generator)
        ▼
assets/source/*.blend                     inspectable .blend sources
packages/client/public/assets/models/*.glb 59 GLB files, 0.59 MB total
packages/client/public/assets/manifest.json
```

---

## Running it

```bash
npm run assets          # regenerate everything (~20 s)
npm run assets:check    # verify the 39 required models exist; no Blender needed
```

Blender is discovered in this order:

1. `BLENDER_PATH` environment variable
2. `tools/.blender-path` (a file containing one path — gitignored)
3. `blender` on `PATH`
4. Standard install locations for Windows, macOS and Linux
5. A portable extraction under `tools/blender/`

```bash
BLENDER_PATH="/path/to/blender" npm run assets
node tools/build-assets.mjs --only weapons     # one generator
node tools/build-assets.mjs --check            # validate, do not rebuild
```

The exported `.glb` files **are committed**. Contributors never need Blender
unless they are changing a model, and CI does not need it at all.

## Why generate instead of model by hand

- **Originality is structural.** There is no step at which a third-party asset
  could enter. The provenance of every vertex is a line of Python.
- **Reviewable diffs.** A weapon change is a readable diff, not an opaque binary.
- **Consistency for free.** Every weapon uses the same material set, the same
  grip proportions and the same socket names, because they call the same helpers.
- **Trivially re-tunable.** Changing the sci-fi palette is one edit in
  `lib_kang.py` and one command.
- **Tiny.** 59 models in 0.59 MB, because the geometry is deliberate rather than
  a decimated sculpt.

The cost is real: silhouettes are blockier than hand-modelled art would be. That
suits the intended low-poly look, and it is the trade that buys everything above.

## `lib_kang.py`

The whole library is deliberately small.

### Materials

`material(name)` returns a cached PBR material from a fixed palette — hull
greys, weapon gunmetal, energy cyan/magenta/amber/lime emissives, glass, rubber
grips, team-tint slots. Cached by name so a joined mesh keeps one material per
distinct surface, which is what keeps draw calls low.

### Primitives

Built from explicit vertex and face lists, not from `bpy.ops` primitives:

| Helper | Shape |
| --- | --- |
| `box(...)` | axis-aligned or yaw-rotated cuboid |
| `wedge(...)` | ramp/prism, used for angled plating |
| `cyl(...)` | n-gon cylinder, explicit segment count |
| `tube(...)` | hollow cylinder — barrels, vents |
| `cone(...)` | muzzle devices, spikes |
| `plate(...)` | thin panel with a bevelled edge |
| `sphere(...)` | icospheres for domes and cores |

Explicit vertex data rather than operators means the result does not depend on
Blender's operator defaults, which drift between versions.

### Assembly

- `join(objects, name)` — merge into a single mesh, preserving material slots.
- `socket(name, location, rotation)` — an empty marking a mount point. Weapons
  expose `muzzle`, `eject`, `grip`, `sight`; characters expose `hand_r`,
  `hand_l`, `head`, `chest`, `back`. The client attaches effects and world
  weapons to these by name, so it never hardcodes an offset.
- `add_uvs(obj)` — box-projected UVs so procedural textures land predictably.
- `decimate_copy(obj, ratio, suffix)` — generates the LOD chain.
- `export_glb(path, objects)` — writes the GLB with Draco off (these meshes are
  too small for Draco to pay for its decode cost).

### LODs

Each character and each world weapon exports LOD0 (full), LOD1 (~60%) and
LOD2 (~30%). The client picks by screen-space size — see
[PERFORMANCE.md](PERFORMANCE.md). First-person models have no LODs; they are
always close.

## The orientation problem, and the fix

**This was a real bug, and it is the single most important thing to understand
before adding a model.**

Blender is **Z-up**. glTF is **Y-up**. The glTF exporter therefore rotates
everything −90° about X on the way out.

The models were authored to look right in the Blender viewport with +Y forward.
On export that became +Y *down*, and every weapon in the game pointed at the
floor.

The fix is `reorient(mode)` in `lib_kang.py`, called at the end of every
generator, which pre-rotates the scene so the exporter's conversion lands on the
intended orientation:

```python
def reorient(mode: str) -> None:
    if mode == "yup":
        matrix = mathutils.Euler((math.radians(90), 0.0, 0.0)).to_matrix().to_4x4()
    elif mode == "face":
        matrix = mathutils.Euler((0.0, 0.0, math.radians(180))).to_matrix().to_4x4()
    else:
        return
    transformed_meshes: set[str] = set()
    for obj in list(bpy.data.objects):
        if obj.type == "MESH":
            # Transform each mesh datablock once: several objects can share one,
            # and applying the matrix twice would undo the correction.
            if obj.data.name not in transformed_meshes:
                obj.data.transform(matrix)
                obj.data.update()
                transformed_meshes.add(obj.data.name)
            obj.location = (matrix @ obj.location.to_4d()).to_3d()
        elif obj.type == "EMPTY":
            obj.location = (matrix @ obj.location.to_4d()).to_3d()
```

| Mode | Used by | Effect |
| --- | --- | --- |
| `"yup"` | weapons, props | +90° X, so authored +Y forward exports as +Z forward |
| `"face"` | characters | 180° Z, so characters face the camera at yaw 0 |

Two details that matter:

- **Mesh datablocks are transformed once each.** Instanced objects share a
  datablock; transforming per-object would apply the matrix repeatedly.
- **Empties are moved by matrix multiplication**, not by transforming a mesh they
  do not have. Sockets have to travel with the geometry or muzzle flashes appear
  in the wrong place.

If a new model comes out rotated, this function is the first place to look.

## Adding a model

### A weapon

1. Add a builder in `assets/scripts/gen_weapons.py`:

   ```python
   def build_my_weapon():
       parts = [
           N.box("body",   (0, 0, 0),      (0.06, 0.05, 0.34), N.material("gunmetal")),
           N.tube("barrel",(0, 0, 0.30),   0.018, 0.012, 0.22,  N.material("gunmetal")),
           N.box("energy", (0, 0.035, 0.02),(0.02, 0.012, 0.10), N.material("energy_cyan")),
       ]
       obj = N.join(parts, "wpn_my_weapon")
       N.add_uvs(obj)
       N.socket("muzzle", (0, 0, 0.52))
       N.socket("grip",   (0, -0.06, -0.04))
       return obj
   ```

2. Register it in the generator's build table (first-person and world variants).
3. Add the stat block to `packages/shared/src/data/weapons.ts`.
4. Add an icon path to `packages/client/src/ui/icons.ts`.
5. Add the model id to the required list in `tools/build-assets.mjs`.
6. `npm run assets && npm test`.

`weapons.test.ts` will fail if the stat block is internally inconsistent — for
example a zero-width damage-falloff window, which is exactly the bug it caught
for two weapons during development.

### A prop

Add a builder to `gen_props.py` and register it. Props used as level geometry must
also exist as brushes in the map (brushes are the collision), so props are
decoration, pickups, objectives and deployables — never something you can stand on.

## Manifest

`tools/build-assets.mjs` writes `packages/client/public/assets/manifest.json`:

```json
{
  "generated": "blender",
  "generator": "assets/scripts/gen_*.py",
  "note": "Every model here is generated from source by the Blender scripts in assets/scripts. Regenerate with: npm run assets",
  "count": 59,
  "totalBytes": 618360,
  "models": {
    "char_arms_fp":  { "file": "models/char_arms_fp.glb",  "bytes": 12520 },
    "char_engineer": { "file": "models/char_engineer.glb", "bytes": 30364 }
  }
}
```

The client reads it at boot to resolve model ids to files and to report the load
in diagnostics. `npm run assets:check` verifies all 39 required models are
present and non-empty without needing Blender, which is what CI runs.

## Inspecting a model

`assets/source/*.blend` is written alongside each export, so you can open a
generated asset, look at it, and check socket placement:

```bash
blender assets/source/weapons.blend
```

Do not edit and re-save it — the next `npm run assets` overwrites it. Change the
Python.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Model points at the floor or the wrong way | `reorient()` mode wrong, or missing. See above. |
| Muzzle flash in the wrong place | Socket not moved by `reorient()`, or a typo in the socket name. |
| Model is black in game | Material missing an emissive/metallic setup, or the environment map has not loaded. The scene uses a PMREM environment; a metal with no envMap renders near-black. |
| Model does not appear | Not registered in the manifest list, or the id in the data table does not match the GLB name. |
| `Blender not found` | Set `BLENDER_PATH` or write the path into `tools/.blender-path`. |
| Export fails on a shared mesh | Two objects share a datablock and something transformed it twice. |
